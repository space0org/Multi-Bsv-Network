# アーキテクチャ概要

このセクションでは、BSVネットワーク（JpyNetworkとLariNetwork）のアーキテクチャと、それらがどのように相互作用するかについて説明します。

## 全体アーキテクチャ

BSVネットワークシステムは、以下の主要コンポーネントで構成されています：

1. **JpyNetwork** - 独立したBSVブロックチェーンネットワーク
2. **LariNetwork** - 独立したBSVブロックチェーンネットワーク
3. **トークンブリッジAPI** - 両ネットワーク間のトークン交換を処理するサービス

これらのコンポーネントは、Dockerコンテナとして実行され、Docker Networkを通じて相互に通信します。

```
+-------------------+       +-------------------+
|                   |       |                   |
|   JpyNetwork      |       |   LariNetwork     |
|   (BSVノード)      |       |   (BSVノード)      |
|                   |       |                   |
+--------+----------+       +---------+---------+
         |                            |
         |                            |
         v                            v
+------------------------------------------+
|                                          |
|           トークンブリッジAPI              |
|                                          |
+------------------------------------------+
         ^
         |
         |
+------------------------------------------+
|                                          |
|           クライアントアプリケーション      |
|                                          |
+------------------------------------------+
```

## コンポーネントの詳細

### JpyNetworkノード

JpyNetworkは、ブロック0から始まる独立したBSVブロックチェーンネットワークです。以下の特徴があります：

- **ポート**: 18332（RPC）、18333（P2P）
- **RPC認証情報**: jpyuser/jpypassword
- **コンセンサスパラメータ**: `-excessiveblocksize=0 -maxstackmemoryusageconsensus=0`
- **データディレクトリ**: `~/Multi-Bsv-Network/one-click-setup/jpynetwork/data`

JpyNetworkノードは、Dockerコンテナ`jpynetwork-node`として実行されます。

### LariNetworkノード

LariNetworkも、ブロック0から始まる独立したBSVブロックチェーンネットワークです。以下の特徴があります：

- **ポート**: 19332（RPC）、19333（P2P）
- **RPC認証情報**: lariuser/laripassword
- **コンセンサスパラメータ**: `-excessiveblocksize=0 -maxstackmemoryusageconsensus=0`
- **データディレクトリ**: `~/Multi-Bsv-Network/one-click-setup/larinetwork/data`

LariNetworkノードは、Dockerコンテナ`larinetwork-node`として実行されます。

### トークンブリッジAPI

トークンブリッジAPIは、JpyNetworkとLariNetwork間のトークン交換を処理するRESTful APIサービスです。以下の特徴があります：

- **ポート**: 5001
- **エンドポイント**: `/bridge/info`, `/wallet/create`, `/wallet/balance`, `/bridge/swap`, `/wallet/transactions`
- **交換レート**: 1 Lari（1 satoshi）= 55 Jpy（55 satoshi）

トークンブリッジAPIは、Dockerコンテナ`token-bridge`として実行されます。

## ネットワーク通信フロー

1. **クライアント → トークンブリッジAPI**: クライアントアプリケーションは、トークンブリッジAPIにHTTPリクエストを送信します。
2. **トークンブリッジAPI → JpyNetwork/LariNetwork**: トークンブリッジAPIは、JSON-RPCを使用してBSVノードと通信します。
3. **JpyNetwork ↔ LariNetwork**: 両ネットワークは、P2P接続を通じて相互に通信します。

## データフロー

### ウォレット作成フロー

1. クライアントが`/wallet/create`エンドポイントにリクエストを送信します。
2. トークンブリッジAPIが新しい秘密鍵と公開鍵のペアを生成します。
3. トークンブリッジAPIがウォレットアドレスと秘密鍵をクライアントに返します。

### 残高確認フロー

1. クライアントが`/wallet/balance?address=<アドレス>&network=<ネットワーク>`エンドポイントにリクエストを送信します。
2. トークンブリッジAPIが指定されたネットワークのBSVノードにRPCリクエストを送信します。
3. BSVノードがアドレスの残高情報を返します。
4. トークンブリッジAPIが残高情報をクライアントに返します。

### トークン交換フロー

1. クライアントが`/bridge/swap`エンドポイントにPOSTリクエストを送信します。
2. トークンブリッジAPIが送信元ネットワークのBSVノードにトランザクションを送信します。
3. トークンブリッジAPIが送信先ネットワークのBSVノードにトランザクションを送信します。
4. トークンブリッジAPIが両方のトランザクションIDをクライアントに返します。

## デプロイメントアーキテクチャ

BSVネットワークシステムは、AWS EC2インスタンス上にデプロイされています。以下のコンポーネントが含まれます：

- **EC2インスタンス**: t2.micro（1 vCPU、1 GBメモリ）
- **リージョン**: ap-southeast-2（シドニー）
- **ストレージ**: 8 GB汎用SSD（gp2）
- **セキュリティグループ**: 以下のポートを許可
  - 22（SSH）
  - 18332、18333（JpyNetwork）
  - 19332、19333（LariNetwork）
  - 5001（トークンブリッジAPI）

## スケーラビリティと拡張性

現在のアーキテクチャは、以下の方法で拡張できます：

1. **ノードの追加**: 各ネットワークに追加のノードを追加して、ネットワークの冗長性と安全性を向上させることができます。
2. **リソースの増加**: EC2インスタンスのサイズを大きくして、より多くのトランザクションを処理できるようにすることができます。
3. **ロードバランシング**: 複数のトークンブリッジAPIインスタンスを作成し、ロードバランサーの背後に配置することができます。

## セキュリティ考慮事項

現在のアーキテクチャには、以下のセキュリティ考慮事項があります：

1. **RPC認証**: BSVノードのRPCインターフェースは、ユーザー名とパスワードで保護されています。
2. **ネットワーク分離**: JpyNetworkとLariNetworkは、独立したネットワークとして実行されています。
3. **秘密鍵の保護**: 秘密鍵はクライアント側で管理され、サーバーには保存されません。
